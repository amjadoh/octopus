# الأخطبوط | Octopus

تطبيق Android شخصي بالعربية وRTL وبالأبيض والبترولي. يُوزَّع الآن **APK واحد فقط**، دون كتالوج أو أسعار تجريبية. كود العرض السابق تحت `src/demo` مرجع معزول ولا يدخل التطبيق الموزع.

## 0.3.0 — فحص سبب فشل القراءة

الإصدار السابق وصل إلى عناصر الواجهة على جهاز فعلي، لكنه انتهى دون إجمالي مقروء. هذا لا يثبت أن عناصر الأسعار متاحة، ولا يحدد وحده سبب الفشل. أضفنا فحصًا صريحًا لعناصر شاشة يختارها المستخدم، وطلب معرفات العناصر عبر `flagReportViewIds`، وتصديرًا منقحًا يفرق بين غياب التسميات وغياب الأرقام والتضارب. لا نفعّل `isAccessibilityTool`، ولا نجري نقرات أو دفعًا داخل منصات التوصيل.

**تجهيز السلة والمقارنة الآلية لم يكتملَا.** فحص الشاشة أداة جمع دليل للتطوير، وليس ميزة مقارنة ناجحة. لا نطلب تكرار الاختبار القديم أو إدخال أسعار يدويًا كل مرة.

من «القراءة» اختر «فحص شاشة مراجعة الطلب»، وحدد المنصة وشاشة المراجعة، ووافق على الفحص. انتقل للمراجعة داخل المنصة ثم اضغط الزر العائم «افحص هذه الشاشة». السجل يحتفظ بمعرفات وأدوار ومواقع وتسميات وظيفية محددة، دون النصوص الخام أو قيم الحقول أو صور الشاشة. التصدير يدوي فقط، ولا صلاحية إنترنت.

يُحفظ فحص العناصر في قاعدة Room مستقلة دون ترحيل مدمر للسجل السابق. حُفظت قاعدة الاختبارات الأصلية. حذف البيانات من إعدادات الأخطبوط يشمل قاعدتي البيانات.

## حدود وشروط المنصات

البند 4.1.6 من [شروط كيتا السعودية](https://www.mykeeta.com/contents/user.html?locale=en&region=SA) يوثق قيدًا على الاستخراج بالبرامج دون إذن كتابي. طلب المستخدم صراحة متابعة الاختبار المحلي الشخصي رغم القيد؛ ذلك لا يمثل موافقة من كيتا ولا يزيل القيد. لا توجد آلية تجاوز حماية أو CAPTCHA أو استخراج جلسة/حساب. راجع [حالة المنصات](docs/PROVIDER_STATUS.md).

## البناء

JDK 17، SDK Platform 35، Build Tools 35.0.0، min SDK 28. لا نفترض إصدار الهاتف؛ يظهر في السجل الفعلي.

```powershell
.\gradlew.bat :app:assembleDiagnosticDebug :app:testDiagnosticDebugUnitTest :app:lintDiagnosticDebug :app:assembleDiagnosticDebugAndroidTest
```

الملف الناتج: `app/build/outputs/apk/diagnostic/debug/app-diagnostic-debug.apk`. توجد فحوص GitHub يدوية، ومسار نشر تجريبي منفصل يدوي لا ينشر قبل نجاح البناء والاختبارات والتوقيع والعزل. اختبارات الواجهة تُجمع؛ تشغيلها يتطلب هاتفًا أو محاكيًا.

راجع [تعليمات التجربة](docs/TEST_ON_PHONE.md) و[التحقق](docs/VALIDATION.md). مفاتيح التوقيع لا تدخل المستودع. يستخدم النشر من 0.3.0 توقيعًا تجريبيًا ثابتًا مع التحقق من بصمته. راجع [تحديث التطبيق](docs/APP_UPDATES.md) لزر الإعدادات والانتقال من توقيع 0.2.0 القديم.
