# الأخطبوط | Octopus

تطبيق Android شخصي بالعربية وRTL وبالأبيض والبترولي. يُوزَّع الآن **APK واحد فقط**، دون كتالوج أو أسعار تجريبية. كود العرض السابق تحت `src/demo` مرجع معزول ولا يدخل التطبيق الموزع.

## 1.3.0 — اختبارات ريدان على الأونر

واجهة مطاعم جديدة تقرأ أسماء فعلية من هنقرستيشن، ثم تعرض مقارنة قبل اختيار منصة تجهيز السلة. النطاق الحي المختبر هو «ريدان / نصف دجاج مضغوط» بلا إضافات أو ملاحظة، بكميات1 و2 و3. أضيف إنشاء السلة ومطابقة العدد وإعادة التحقق عند التسليم في هنقرستيشن وكيتا، دون تأكيد طلب أو دفع. قراءة المطاعم ليست ادعاء دعم تجهيز كل قوائمها.

المقارنة تحسب شروط العروض المقروءة، ومنها الحد الأدنى وسقف الخصم والتوصيل المجاني وصلاحية القسيمة. لا تجمع عرضين دون دليل جمع، ولا تعلن إجمالي مراجعة الطلب أو الأرخص مع رسوم غير متحققة. رسوم الخدمة والفرع والعنوان ما زالت تحتاج استكمال التحقق؛ التفاصيل والأدلة في [سياق العمل الحالي](CONTINUE_HERE.md) و[حالة التنفيذ](docs/PRODUCT_EXECUTION_STATUS.md).

النسخة تحافظ على توقيع التطبيق وبياناته، رقم البناء8، واجتازت180 اختبار وحدة وlint. ملفات APK الموقعة تحفظ كـ`honor-signed-device-test` في [تشغيل بناء الجهاز](https://github.com/amjadoh/octopus/actions/runs/39324947651)، وليست إصدارًا يعلن اكتمال المقارنة النهائية. يتوفر APK بعد نجاح البناء ورفع artifact، لمدة90 يومًا. لا تحذف التطبيق الأصلي لتثبيت ملف debug محلي مختلف التوقيع.

## 1.2.0 — خيارات الوجبة والطلب المحفوظ (تجريبي)

معاينة للعمل الحالي بناءً على طلب المستخدم قبل استكمال التجهيز والمقارنة على الجهاز. تضيف خيارات الوجبة المدعومة وحفظ الطلب محليًا وتعديل الكميات، وإصلاح التمرير والرجوع، وسجل تعطل منقحًا أثناء الجلسة. نمط الخيارات القابل للاختيار محصور بعينة «المضياف العربي — دجاج مظبي»؛ لا يدّعي دعم قوائم جميع المطاعم. الطلب المحفوظ لا يعد سلة مجهزة داخل منصة توصيل.

المقارنة الفعلية وتجهيز سلتَي كيتا وهنقرستيشن غير مكتملين. راجع [ملاحظات الإصدار](docs/PREVIEW_RELEASE.md). نشر المعاينة لا يحول بوابة المقارنة الكاملة إلى ناجحة. يظل التوقيع ثابتًا، ورقم البناء يرتفع إلى 7.

## 1.1.0 — بحث المطاعم والقوائم (تجريبي)

شاشة المطاعم تقرأ نتائج البحث والقائمة من واجهة هنقرستيشن الفعلية، بعد موافقة منفصلة، ثم تعرضها داخل الأخطبوط. قد تكون القائمة جزئية، وأسعار الأصناف ليست إجماليات نهائية. لا توجد أسعار عرض داخل وضع الاستخدام الحقيقي.

**المقارنة الفعلية بين كيتا وهنقرستيشن وتجهيز السلتين غير مكتملين في هذا الإصدار.** لا تتضمن موافقة قراءة القوائم تعديل سلة أو طلبًا أو دفعًا. يتوقف المحرك عند شاشة أو إصدار غير متحقق.

راجع [ملاحظات الإصدار الحالي](docs/PREVIEW_RELEASE.md) و[دليل التحقق وحدوده](docs/DEVICE_VALIDATION_1.1.0.md). التحديث فوق 1.0.0 يحتفظ بالشهادة والبيانات. اختبارات الوحدة والفحص واختبارات التشغيل تسبق نشر APK التجريبي.

## 1.0.0 — إصلاح الإغلاق عند التشغيل

حُوّل تحميل الشعار إلى PNG مباشرة لتجنب استثناء تحميل XML من النوع bitmap. يلزم نجاح اختبارات تشغيل الواجهة على محاكي API 35 قبل النشر. التحديث فوق 0.3.0 يحافظ على التوقيع والبيانات. يبقى فحص القراءة وتجهيز السلة على الهاتف غير متحققين.

## 0.3.0 — فحص سبب فشل القراءة

الإصدار السابق وصل إلى عناصر الواجهة على جهاز فعلي، لكنه انتهى دون إجمالي مقروء. هذا لا يثبت أن عناصر الأسعار متاحة، ولا يحدد وحده سبب الفشل. أضفنا فحصًا صريحًا لعناصر شاشة يختارها المستخدم، وطلب معرفات العناصر عبر `flagReportViewIds`، وتصديرًا منقحًا يفرق بين غياب التسميات وغياب الأرقام والتضارب. لا نفعّل `isAccessibilityTool`، ولا نجري نقرات أو دفعًا داخل منصات التوصيل.

**تجهيز السلة والمقارنة الآلية لم يكتملَا.** فحص الشاشة أداة جمع دليل للتطوير، وليس ميزة مقارنة ناجحة. لا نطلب تكرار الاختبار القديم أو إدخال أسعار يدويًا كل مرة.

من «القراءة» اختر «فحص شاشة مراجعة الطلب»، وحدد المنصة وشاشة المراجعة، ووافق على الفحص. انتقل للمراجعة داخل المنصة ثم اضغط الزر العائم «افحص هذه الشاشة». السجل يحتفظ بمعرفات وأدوار ومواقع وتسميات وظيفية محددة، دون النصوص الخام أو قيم الحقول أو صور الشاشة. التصدير يدوي فقط، ولا صلاحية إنترنت.

يُحفظ فحص العناصر في قاعدة Room مستقلة دون ترحيل مدمر للسجل السابق. حُفظت قاعدة الاختبارات الأصلية. حذف البيانات من إعدادات الأخطبوط يشمل قاعدتي البيانات.

## حدود وشروط المنصات

البند 4.1.6 من [شروط كيتا السعودية](https://www.mykeeta.com/contents/user.html?locale=en&region=SA) يوثق قيدًا على الاستخراج بالبرامج دون إذن كتابي. طلب المستخدم صراحة متابعة الاختبار المحلي الشخصي رغم القيد؛ ذلك لا يمثل موافقة من كيتا ولا يزيل القيد. لا توجد آلية تجاوز حماية أو CAPTCHA أو استخراج جلسة/حساب. راجع [حالة المنصات](docs/PROVIDER_STATUS.md).

## البناء

JDK 17، SDK Platform 35، Build Tools 35.0.0، min SDK 28. لا نفترض إصدار الهاتف؛ يظهر في السجل الفعلي.

```powershell
.\gradlew.bat :app:assembleDiagnosticDebug :app:testDiagnosticDebugUnitTest :app:lintDiagnosticDebug :app:assembleDiagnosticDebugAndroidTest
```

الملف الناتج: `app/build/outputs/apk/diagnostic/debug/app-diagnostic-debug.apk`. توجد فحوص GitHub يدوية، ومسار نشر تجريبي منفصل يدوي لا ينشر قبل نجاح البناء والاختبارات والتوقيع والعزل. اختبارات الواجهة تُجمع؛ تشغيلها يتطلب هاتفًا أو محاكيًا.

راجع [تعليمات التجربة](docs/TEST_ON_PHONE.md) و[التحقق](docs/VALIDATION.md). مفاتيح التوقيع لا تدخل المستودع. يستخدم النشر من 0.3.0 توقيعًا تجريبيًا ثابتًا مع التحقق من بصمته. راجع [تحديث التطبيق](docs/APP_UPDATES.md) لزر الإعدادات والانتقال من توقيع 0.2.0 القديم.
